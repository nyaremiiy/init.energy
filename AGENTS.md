# init.energy — інструкції для AI-агентів

Цей файл — **єдине джерело правил** для всіх AI-агентів у проєкті (Codex читає його напряму, Claude Code — через `CLAUDE.md`). Власник проєкту працює то з Claude Code, то з Codex, тому кожен агент **обов'язково** синхронізується через спільні файли нижче.

## Перед початком будь-якої роботи

1. Прочитай [`docs/ai/CONTEXT.md`](docs/ai/CONTEXT.md) — поточний стан проєкту, архітектура, прийняті рішення.
2. Прочитай [`docs/ai/CHANGELOG.md`](docs/ai/CHANGELOG.md) — журнал змін (нові записи зверху).
3. Перевір git: `git status`, `git branch`, `git log --oneline -15 --all` — зміни могли зробити поза журналом.

## Після завершення задачі

1. Додай запис у **верх** `docs/ai/CHANGELOG.md` за шаблоном у цьому файлі.
2. Якщо змінилась архітектура, стек, структура, команди чи прийняті рішення — онови `docs/ai/CONTEXT.md`.
3. Закоміть ці файли **разом зі змінами коду** у гілці задачі.
4. Змерджи готову гілку в `develop` через `git merge --no-ff` і запуш `develop` у `origin`.

## Межі роботи — лише у папці проєкту

- Читаємо й змінюємо файли **тільки всередині папки проєкту** (репозиторію).
- Не шукаємо і не відкриваємо файли поза проєктом: ні на Desktop, ні в Downloads, ні в інших папках користувача, навіть для пошуку джерел чи оригіналів фото.
- Якщо потрібен файл поза проєктом, спершу питаємо власника і чекаємо явного шляху.
- Тимчасові файли пишемо тільки в scratchpad, який вказано в середовищі сесії.

- Видаляй невикористовувані файли, імпорти, змінні, компоненти та інший мертвий код, якщо вони більше не потрібні проєкту.

- Використовуй актуальний канонічний синтаксис Tailwind CSS: обирай стандартні utility-класи замість довільних значень, якщо доступний семантично еквівалентний клас; враховуй рекомендації Tailwind CSS IntelliSense.
- Верстку завжди роби за принципом **mobile-first**: базові стилі призначені для малих екранів, а зміни для більших — додаються через responsive-брейкпоінти.
- Новий код пиши з урахуванням **SEO**: семантична HTML-структура, коректні metadata, ієрархія заголовків, доступні `alt`-описи, швидке завантаження та індексація.
- Новий контент і структуру також готуй для **GEO (Generative Engine Optimization)**: чіткі самодостатні формулювання, зрозумілий контекст, структуровані дані та відповіді на реальні запити користувачів.

- Іконки інтерфейсу — лише `lucide-react`. Виняток: логотипи соцмереж (Facebook, Instagram, LinkedIn, TikTok) — власні SVG у `src/components/ui/social-icons.tsx`, бо в lucide-react v1 бренд-іконок немає.

## Дизайн-токени (обов'язково)

Кольори, типографіка, радіуси й тіні задаються лише токенами `@theme` у `src/app/globals.css`. Власних hex-кольорів, довільних значень (`-[…]`) і розмірів поза шкалою не пишемо. Прозорість — лише через токени `muted`, `faint`, `line`, `hover`, `fill-dark`, `line-dark`, `faint-dark`, `muted-dark`; класи на кшталт `ink/60` або `white/25` заборонені (виняток — декоративний `FooterMark`). `npm run lint` запускає `scripts/lint-tokens.mjs` і падає на порушеннях.

### Кольори

- `ink` rgb(0 2 23) — основний текст на світлому фоні, темні панелі, кнопки `dark`.
- `white` — текст і поверхні на темному фоні (стандартний Tailwind, без прозорості).
- `surface` — світлий фон картки й секції; `sky` — блакитна панель калькулятора; `navy` — друга темна картка й hover світлої картки.
- На світлому: `muted` (ink 70%) — другорядний текст · `faint` (ink 40%) — плейсхолдери, disabled, пунктир · `line` (ink 12%) — лінії й рамки · `hover` (ink 6%) — hover-заливка, водяні знаки.
- На темному: `muted-dark` (white 75%) — другорядний текст · `faint-dark` (white 45%) — плейсхолдери, пунктир · `line-dark` (white 16%) — лінії й рамки · `fill-dark` (white 8%) — картки й hover-заливка.
- `accent` / `accent-strong` — лише індикатори ємності, шкали й графіка; ніколи текст чи кнопки. `success` — лише іконка успіху в сповіщенні.
- Градієнти фото (`scrim-*`, зокрема `scrim-lead` для фото в секції заявки), маски `mask-promo-curve` / `mask-promo-curve-bottom` і фони `bg-ink-glow` (світіння з верхніх кутів: футер, шапка, меню), `bg-ink-glow-start` (те саме світіння з лівого верхнього кута, за текстом: `PromoBanner`), `fade-from-ink` — у `globals.css`; прозорість у них дозволена.

### Типографіка

- `font-heading` — Montserrat: 300 для великих цифр, 500 для лейблів і значень, 600 для заголовків.
- `font-sans` — Inter: 400 для тексту, 500 для кнопок, меню й акцентів, 600 лише для кнопок. Ваги 700+ не використовуємо (`font-bold` і `font-extrabold` заборонені, замість них `font-semibold`).
- Розміри: `text-hero-*`, `text-h2-*`, `text-h3-*`, `text-stat-*`, `text-number-*`, `text-eyebrow-*`, `text-display` (водяний знак), `text-lead` (18 px, лід), `text-body` (16 px), `text-small` (14 px, UI і вторинний текст), `text-caption` (13 px, лише дрібний шрифт). Класи Tailwind `text-xs`, `text-sm`, `text-base`, `text-lg` заборонені.

### Радіуси

- `rounded-panel` / `rounded-panel-sm` — великі панелі; `rounded-card` (24 px) — картки; `rounded-tile` (16 px) — дрібні блоки, пігулки-квадрати, мініатюри; `rounded-field` (14 px) — поля вводу.
- `rounded-full` — кола й пігулки; `rounded-sm` — лише фокус-обводка посилань.
- `rounded-md`, `rounded-lg`, `rounded-xl`, `rounded-2xl`, `rounded-3xl` заборонені.

### Тіні (три токени, більше не додаємо)

- `shadow-soft` — hero, випадаюче мега-меню, плаваюча кнопка повернення вгору і сповіщення.
- `shadow-card` — світлі картки, калькулятор, форма заявки, тултіп.
- `shadow-glass` — лише плаваючі скляні елементи: банер і вікно cookie (разом з `bg-glass`).

## Кнопки й посилання (обов'язково)

Кожна кнопка і посилання на сайті — один із компонентів у `src/components/ui/`: `Button`, `IconButton`, `ArrowLink`, `InlineLink`, `NavLink`, `PillLink`, `RowLink`, `chipClasses` (фільтри, вкладки, радіо-пігулки). Власні класи для `rounded-full` або `underline` на `<a>`, `<Link>` чи `<button>` поза `ui/` заборонені; `npm run lint:tokens` падає на порушеннях і друкує задокументовані винятки.

- Навігація → `<a>` / `Link`; дія → `<button>`. Вигляд однаковий, тег різний (`Button` сам обирає тег через `href`).
- Не більше одного `dark` або `primary` на екран; поруч — лише `outline-light` / `secondary` або `ArrowLink`.
- Стрілка — тільки `ArrowUpRight`: 18 px у кнопках, 16 px у текстових посиланнях; зсувається на 2 px при hover лише з `motion-safe`.
- Шрифти: `Button` — Montserrat 600, 14 px; `ArrowLink` — Inter 600, 16 px; `chipClasses` і `PillLink` — Inter 500, 14 px; `NavLink` — Inter 400, 14 px.
- Фокус завжди видно: `Button` — 4 px, зсув 2 px; `IconButton`, `chipClasses`, `PillLink` — 2 px, зсув 2 px; текстові посилання — 2 px, зсув 4 px.
- Ціль натискання на мобільному ≥ 44×44. `Button size="sm"` (40 px) — лише на десктопних банерах і діалогах.
- `Button` з `loading` показує спінер і блокує кнопку; для submit форм використовуємо його, а не власний спінер.

## Форми

Кожен контрол — через компоненти `src/components/ui/form/`: `Field` / `FieldGroup` (підпис, контрол, рядок повідомлення), `TextInput`, `NumberInput` (з `unit`), `Textarea`, `Select`, `RadioPills` (`variant="pills"` або `"tiles"` — плитки з іконками, тип об'єкта в заявці) / `PillRadio`, `CheckChip`, `Checkbox`, `Switch`, `RangeField`, `CheckTile` (плитка-чекбокс з іконкою: вибір приладів), `FormCard`. Стилі полів — лише `inputClasses`. `npm run lint:tokens` падає на `<input>`, `<select>`, `<textarea>` поза `ui/form/` (крім `type="hidden"` і honeypot з `data-honeypot`).

- Підпис видно завжди; placeholder — лише приклад («Наприклад, 40»). Позначаємо необов'язкові поля, не обов'язкові.
- Помилка: рамка ink / white + іконка `AlertCircle` + текст, без червоного; фокус на першому полі з помилкою (`focusFirstInvalid`); у формах заявки місце під повідомлення зарезервоване (`reserveMessage`).
- Текст поля 16 px, висота 56 px — і на мобільному (без zoom в iOS).
- Правильні `type`, `inputMode`, `autoComplete` для кожного поля (ім'я — `name`, телефон — `tel`, email — `email`).
- Вибір — нативні контроли (radio, checkbox, select, range), лише стилізовані; перемикач — `button role="switch"`.

## Git workflow (обов'язково)

- `main` — стабільна гілка. **Мерджить у `main` тільки власник.** Агентам заборонено комітити чи мерджити в `main`.
- `develop` — інтеграційна гілка.
- Кожна задача — окрема гілка від актуального `develop`:
  - `feature/<коротка-назва>` — новий функціонал
  - `fix/<коротка-назва>` — виправлення
  - `chore/<коротка-назва>` — налаштування, інфраструктура, документація
- Готову задачу мерджимо в `develop` через `git merge --no-ff`.
- Після кожної завершеної та перевіреної задачі обов'язково пушимо оновлений `develop` у `origin/develop`; окремого підтвердження власника не чекаємо.
- Повідомлення комітів — Conventional Commits англійською: `feat: ...`, `fix: ...`, `chore: ...`, `docs: ...`.
- Перед мерджем: `npm run lint` і `npm run build` мають проходити.
